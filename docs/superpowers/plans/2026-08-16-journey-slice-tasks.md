# Journey slice TASK implementation

- Runtime derives TASK queues from planned E2E obligations by journey.
- Overloaded journeys split; collection obligations larger than 3 items are rejected.
- First TASK absorbs the minimum shell. Agent refinements cannot merge, drop, or dump E2E onto a leftover TASK.
- `record_task_executed_evidence()` plus prototype conformance are required before TASK completion.
- Full browser evidence accepts the slice union plus regression.
- Confirmed `test_coverage_plan` deliveries stay grandfathered until that plan is reopened.
