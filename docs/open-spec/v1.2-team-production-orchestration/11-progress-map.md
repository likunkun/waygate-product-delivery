# V1.2 产品交付地图（CR-006）

状态：实现与验收完成。用户批准：静态 HTML、每 1 分钟刷新、离线快照；复用已有 HTTP 服务；项目默认＋交付覆盖，初始关闭。刷新间隔在 1.2.1 按用户反馈由 5 秒调整为 1 分钟。

## 需求与边界

地图回答产品目标、模块协作、当前工作、剩余缺口和计划变化。适用 UI/non-UI、team/coordinator。模块关联到目标、版本、场景/测试义务、TASK 和工作包。显示实际生产、整合、验证、评审及交付层次，不以代码或任务数量推断产品完成度。未来规划不属于本次遗漏。

开关和地图资料独立于 canonical state，不能推进 Goal/TASK、批准需求或改变评审输入。项目默认只影响新交付；交付恢复保持已解析选择；旧交付无配置时关闭。关闭保留历史，并冻结已有实时页；新交付关闭时已有入口显示关闭提示，不能冒充旧交付的进度。

## 公共入口

插件简写：`map`、`map on`、`map off`、`map default on`、`map default off`、`map export`。执行脚本为 `waygate-map.py --project-root <repo> ...`，只生成文件，不提供 HTTP 服务或后台任务。Python facade：`set_progress_map_mode()`、`record_progress_map_plan()`、`build_progress_map()`、`export_progress_map()`。

## 数据契约

`ProgressMapPlan v1` 包含当前 delivery ID、版本、目标、成功标准、版本目录、组件、能力、接口/依赖、任务关联、变化说明和来源。来源使用项目相对路径＋实际 SHA-256；任务关联使用 delivery ID＋TASK ID＋planned_task_hash。组件与能力拥有稳定 ID，关系不得悬空。关联场景和测试义务使用现有 ID。

计划修订不可变，登记使用 expected_revision 防止覆盖。来源在登记时验证；后续变更显示失效，不静默改变原始计划。批准标记须匹配 canonical 确认记录；仅有说明或调用方自报 approved 不构成批准。已有资料不足时明确标注未知，不能伪造旧计划。展示计划不取代规格或确认。

变化分为原计划、实现细化、评审补漏、已批准范围调整、待解释新增及资料/证据失效。展示依据、影响、负责人和下一步。关联检查是提示，不新增门禁；语义偏差来自生产/独立评审发现，不能由词语相似性推断。

## 存储与刷新

项目默认保存在 `.product-delivery/progress-map-settings.json`。每个 delivery 的 `progress-map/` 保存配置、不可变计划修订、渲染回执与快照。实时入口为 `.product-delivery/maps/index.html`。状态成功落盘后 best-effort 原子刷新派生 HTML；失败只记录展示诊断，不能使已提交的生产操作失败。阶段、确认基线和闭包变化自动留快照。关闭时不生成新地图或快照。

实时 HTML 每 1 分钟带缓存规避参数刷新，并保留选择、筛选和位置。离线 HTML 禁用定时刷新，无外部脚本/字体/CDN；证据附件仅提供路径与携带情况。内容安全转义，禁止路径越界和符号链接绕过。没有服务端 API。

## 验收

1. 默认关闭、项目默认不追溯、交付覆盖、恢复、错误 delivery 拒绝、开关不改变权威状态字节。
2. 中途开启、关闭冻结、重新开启、切换交付、关闭时 export 拒绝。
3. 计划修订冲突、来源失效、跨交付同名 TASK、未关联任务、未来能力、合法批准依据与缺失历史。
4. 六阶段、并行工作包、阻塞、整改、暂停恢复、当前任务、验证与闭包状态。
5. 原子刷新失败保留旧页、错误显式可查、自动里程碑快照、离线交互与安全转义。
6. 浏览器验证五时点故事、刷新保留视图、移动端、关闭后无刷新、离线无网络。
7. 全量 Python 回归、runtime 一致性、无源码 CLI 及分发包验证。

实际验证记录见 [验收报告](12-progress-map-verification.md)。[五时点示例](../../examples/progress-map/index.html) 为展示表达方式的独立离线样例，不作为真实交付批准或验收证据。
